# تتبع غياب التلاميذ — نسخة Vercel (استضافة سحابية دائمة)

هذه نسخة من التطبيق مُعدّة للنشر على Vercel، بحيث يحصل التطبيق على رابط عام دائم
تفتحه كل المكاتب في نفس الوقت، والبيانات تُحفظ وتتشارك تلقائيًا بينها، دون أي
حاجة لتشغيل حاسوب كخادم (لا حاجة لملف server.py ولا لبقاء أي جهاز مفتوحًا).

## محتويات المجلد

- `index.html` — واجهة التطبيق (شاشة الدخول + الجدول).
- `api/auth.js` — الدخول وإنشاء الحسابات (المسؤول / الأستاذ / حسابات الاطلاع).
- `api/backups.js` و`api/_backup.js` — نسخ احتياطية تلقائية للورقة واسترجاعها (للمسؤول).
- `api/mark.js` — تسجيل أو حذف غياب خانة واحدة (للأستاذ وللمسؤول)، والخادم يفرض قواعد اليوم والحصة والاسم.
- `api/state.js` — قراءة وحفظ بيانات الغياب؛ القراءة لأي حساب، والكتابة للمسؤول فقط.
- `api/history.js` — مصدر صفحة الإحصائيات (يومي / أسبوعي / شهري).
- `api/season.js` — أرشيف المواسم الدراسية (أرشفة الغياب السنوي والاطلاع عليه).
- `api/_lib.js` و`api/_seed.js` و`api/_stats.js` — ملفات مساعدة للخادم (لا تُعرض كروابط).
- `package.json` — يذكر الاعتماد على حزمة `@upstash/redis`.

## خطوات النشر

### 1. إنشاء حساب ورفع المشروع

1. أنشئ حسابًا مجانيًا على [vercel.com](https://vercel.com) (يمكن التسجيل
   مباشرة عبر GitHub أو البريد الإلكتروني).
2. **مهم — اختاروا طريقة الرفع بعناية، لأن هذا يحدّد كيف ستُحدَّث الصفحة
   لاحقًا:**
   - **عبر GitHub (المستحسن)**: ارفعوا هذا المجلد إلى مستودع (repository)
     جديد على GitHub، ثم من Vercel اختاروا **Add New... → Project → Import
     Git Repository** واربطوه بذلك المستودع. هذه الطريقة تجعل أي تحديث
     مستقبلي بسيطًا: تعدّلون الملف على GitHub وVercel ينشر النسخة الجديدة
     تلقائيًا على **نفس الرابط**.
   - **بالسحب والإفلات المباشر (Vercel Drop)**: ممكن للنشر الأول فقط، لكن
     انتبهوا: **كل عملية سحب وإفلات جديدة تُنشئ مشروعًا منفصلًا جديدًا
     برابط مختلف تمامًا** — Vercel Drop لا يُحدّث مشروعًا قائمًا مهما فعلتم.
     فإن استخدمتم هذه الطريقة، لتحديث الملفات لاحقًا (بعد النشر الأول) يجب
     ربط المشروع بـ GitHub بأثر رجعي من **Settings → Git → Connect Git
     Repository** بدل إعادة السحب والإفلات، وإلا فقدتم رابطكم الحالي وكل
     الإعدادات المرتبطة به (قاعدة البيانات، كلمة المرور...).
3. اترك كل الإعدادات على الوضع الافتراضي واضغط **Deploy**.

### 2. ربط قاعدة بيانات Redis عبر Upstash (خطوة ضرورية لمرة واحدة)

بدون هذه الخطوة، الصفحة تعمل لكنها لا تستطيع مشاركة البيانات بين الأجهزة.

ملاحظة: خدمة **Vercel KV** القديمة توقفت (تم استبدالها في ديسمبر 2024)،
فلن تجدوا خيارًا باسم "KV" في القائمة. البديل الرسمي المقدَّم من نفس متجر
Vercel (Marketplace) هو تكامل باسم **Upstash Redis**، وهو ما يستخدمه هذا
الملف. إن كانت واجهتكم بالفرنسية، ابحثوا عن الكلمات: **Stockage**
(Storage) ثم **Marketplace** أو **Browse Storage**، ثم اكتبوا **Upstash**
أو **Redis** في مربع البحث — الكلمتان "Upstash" و"Redis" لا تُترجَمان.

1. بعد نجاح النشر، افتح المشروع من لوحة تحكم Vercel.
2. اذهب إلى تبويب **Storage** (أو **Stockage** بالفرنسية).
3. اضغط على **Create Database** أو **Browse Marketplace** (أو ما يقابلها
   بالفرنسية)، ثم ابحثوا عن **Upstash**.
4. اختاروا تكامل **Upstash Redis**، واضغطوا **Add Integration** أو
   **Install** (**Installer**)، ثم أنشئوا قاعدة بيانات جديدة (اختاروا
   المنطقة الأقرب لكم إن طُلب ذلك) واربطوها بهذا المشروع (**Connect
   Project**).
5. بعد الربط، أعيدوا نشر المشروع مرة واحدة (تبويب **Deployments** → القائمة
   بجانب آخر نشر → **Redeploy**) حتى يحصل التطبيق على متغيرات الاتصال
   بقاعدة البيانات.

### 3. الحسابات والصلاحيات (ضروري)

- **المسؤول**: البريد `karama252@gmail.com` فقط. يطّلع ويعدّل. كلمة مروره هي
  متغيّر `ADMIN_PASSWORD` (لا تُحفظ في الكود). لا يمكن لأحد إنشاء حساب بهذا
  البريد من نموذج التسجيل.
- **باقي المستخدمين**: ينشئون حسابًا ببريدهم وكلمة مرور (8 أحرف فأكثر) من تبويب
  «إنشاء حساب»، ويحصلون على صلاحية **الاطلاع فقط**. الخادم يرفض أي محاولة كتابة
  منهم (حتى لو عبثوا بالصفحة).
- بدون تسجيل الدخول لا يظهر أي شيء من البيانات؛ وأسماء التلاميذ لم تعد داخل
  ملف الصفحة العام.

**الإعداد (مرة واحدة)** في Vercel → المشروع → **Settings → Environment
Variables**، أضيفوا متغيّرين:

| الاسم | القيمة |
|---|---|
| `ADMIN_PASSWORD` | كلمة مرور المسؤول التي تختارونها (قوية وطويلة) |
| `SESSION_SECRET` | سلسلة عشوائية طويلة (32 حرفًا على الأقل) تُوقَّع بها الجلسات؛ لا تشاركوها |

ثم **Deployments → (…) → Redeploy**. المتغيّر القديم `APP_PASSWORD` لم يعد
مستعملًا ويمكن حذفه.

ملاحظات:
- الجلسة تدوم 30 يومًا على الجهاز. لإخراج الجميع فورًا غيّروا `SESSION_SECRET`.
- لتغيير كلمة مرور المسؤول: عدّلوا `ADMIN_PASSWORD` وأعيدوا النشر.
- محاولات الدخول محدودة (10 محاولات كل 15 دقيقة لكل بريد/جهاز).
- لا يوجد تأكيد للبريد الإلكتروني: أي شخص يملك الرابط يستطيع إنشاء حساب اطلاع.

### 4. الاستخدام

بعد اكتمال ما سبق، ستجد رابطًا عامًا دائمًا يشبه:

```
https://ghiyab-app-xxxx.vercel.app
```

هذا هو الرابط الذي يفتحه كل مستخدم (بعد تسجيل الدخول أو إنشاء حساب). أي
تعديل (تسجيل غياب، إضافة تلميذ، استيراد لائحة...) يظهر تلقائيًا لدى كل من
يفتح نفس الرابط خلال ثوانٍ، بفضل التحديث الدوري كل 1.5 ثانية.

## ملاحظات

- الخطة المجانية على Vercel تكفي هذا الاستخدام (حجم البيانات صغير جدًا مقارنة
  بحدود الخطة المجانية لكل من Vercel وUpstash).
- **لتحديث التطبيق لاحقًا (مهم)**: إن كان المشروع مربوطًا بـ GitHub، عدّلوا
  الملف على GitHub (مباشرة من المتصفح أو برفع ملف جديد فوق القديم) وVercel
  سينشر النسخة الجديدة تلقائيًا على نفس الرابط خلال دقيقة تقريبًا. **لا
  تستخدموا السحب والإفلات المباشر على Vercel لتحديث مشروع قائم** — هذا
  دائمًا يُنشئ مشروعًا جديدًا منفصلًا برابط مختلف، ويفقدكم كل الإعدادات
  الحالية (قاعدة البيانات، كلمة المرور، الرابط الذي شاركتموه). إن لم يكن
  مشروعكم مربوطًا بـ GitHub بعد، اربطوه أولًا من **Settings → Git → Connect
  Git Repository** قبل أي تحديث.

## استعمال التطبيق لمؤسسة أخرى (نفس الكود، مشروع Vercel مستقل)

أنشئوا مشروع Vercel ثانيًا مربوطًا بنفس المستودع، واربطوه بنفس قاعدة Upstash Redis
(Storage ← Connect Project)، ثم أضيفوا له هذه المتغيّرات ليحصل على بيانات وحسابات منفصلة تمامًا:

| الاسم | القيمة |
|---|---|
| `KEY_PREFIX` | بادئة فريدة لمفاتيح هذه المؤسسة (مثال `marjaiya`)؛ الافتراضي `ghiyab` |
| `ADMIN_EMAIL` | بريد مسؤول هذه المؤسسة |
| `ADMIN_PASSWORD` | كلمة مرور المسؤول |
| `SESSION_SECRET` | سلسلة عشوائية مختلفة عن بقية المؤسسات (32 حرفًا فأكثر) |
| `INSTITUTION_NAME` | اسم المؤسسة الظاهر في الورقة (اختياري) |
| `LOGO_FILE` | اسم ملف الشعار داخل المجلد `logos` (مثال `marjaiya.jpg`)؛ بدونه يظهر الشعار الافتراضي (اختياري). الشعار الذي يرفعه المسؤول من التطبيق يتقدّم عليه |
| `SEED_BLANK` | `1` للبدء بقسم فارغ بدل لوائح المؤسسة الأولى (اختياري) |
| `SEED_DEMO` | `1` أو `2` لموقع **تدريبي** بمؤسسة وهمية (انظروا `docs/training/README.md`): `1` جدول أوقات فارغ، `2` جدول جاهز (اختياري، لا يعمل إلا عند خلو القاعدة) |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS` (+ `SMTP_PORT`, `SMTP_FROM`, `PUBLIC_URL`) | لإرسال دعوات الأساتذة بالبريد (انظروا «دعوة الأساتذة بالبريد»)؛ بدونها تُنسخ الروابط وتُرسل بواتساب (اختياري) |

## الإحصائيات (يومي / أسبوعي / شهري)

زر «📊 الإحصائيات» في أعلى الصفحة (متاح لكل الحسابات) يعرض مجموع ساعات الغياب وعدد التلاميذ
الغائبين ونسبتهم، **حسب التلاميذ أو حسب الأقسام أو حسب المستويات الدراسية**، يوميا أو أسبوعيا أو شهريا.

- **المرشّحات**: القسم والمستوى (تنطبق على الجدول والمبيانات والطباعة والتصدير).
- **المبيانات**: مبيان أعمدة أفقية للمجموعة المختارة (ساعات الغياب أو عدد الغائبين/أيام الغياب)
  + مبيان «التطور اليومي» عند اختيار أسبوع أو شهر. في عرض التلاميذ يُعرض أكثر 20 تلميذا غيابا.
- **الاستخراج**: «تحميل المبيانات (صورة PNG)»، و«تصدير إلى إكسيل» (ورقتان: الإحصائيات والتطور اليومي؛
  وملف CSV إذا تعذّر تحميل مكتبة إكسيل)، و«طباعة الإحصائيات» التي تتضمن المبيانات والجدول.
- تفاصيل التلاميذ تُحفظ مع ملخّص كل أسبوع (`abs` في `api/_stats.js`: الاسم + 30 خانة 0/1 للتلاميذ
  الذين غابوا فقط). الأسابيع المحفوظة قبل هذا التحديث لا تتضمنها، فتظهر لها رسالة توضيحية في عرض التلاميذ.

- الورقة تحتوي أسبوعا واحدا؛ ولحفظ الأسابيع السابقة يُخزَّن عند كل حفظ ملخّص صغير للأسبوع
  (مفتاحه يوم الاثنين المحسوب من تاريخ «من») في Redis تحت `<KEY_PREFIX>:history`.
  لذلك يجب تحديد تاريخ «من» لكل أسبوع.
- زر «⏩ التالي» (للمسؤول) يحفظ الأسبوع الحالي في السجل، يمسح الغياب، ويُقدّم التواريخ 7 أيام.
- المستوى الدراسي يُستنتج من اسم القسم (`1AIPC-2` ← `1AIPC`) ويمكن للمسؤول تعديله من صفحة الإحصائيات.

## العمل عند انقطاع الإنترنت

- إذا انقطع الإنترنت والصفحة مفتوحة، يستمر المسؤول في تسجيل الغياب وإضافة التلاميذ؛ يظهر الشريط «🟠 دون اتصال» وتُحفظ التعديلات على الجهاز، ثم **تُرسَل تلقائيا** عند عودة الاتصال (ويصبح الشريط 🟢).
- الصفحة نفسها تُفتح دون إنترنت (ملف `sw.js` يحتفظ بنسخة منها)، وتُعرض آخر بيانات حُمّلت على الجهاز. يشترط أن يكون الجهاز قد فتح التطبيق مرة واحدة على الأقل بعد هذا التحديث وهو متصل.
- إن عُدّل الجدول من جهاز آخر أثناء الانقطاع، تظهر نافذة تسأل: الاحتفاظ بتعديلات هذا الجهاز أم اعتماد نسخة الخادم.
- إن انتهت صلاحية الدخول والتعديلات غير مرسلة، تبقى محفوظة وتُرسَل بعد تسجيل الدخول من جديد. وزر «خروج» يسأل أولا إن كانت هناك تعديلات غير مرسلة.
- حساب الاطلاع يعرض آخر بيانات محفوظة على جهازه أثناء الانقطاع، دون تحديث.
- لا يعمل دون إنترنت: الإحصائيات وقائمة التعويض (تحتاجان السجل من الخادم)، وتسجيل الدخول لأول مرة، وإرسال واتساب. **حساب الأستاذ يعمل دون إنترنت** (انظروا قسم «حساب أستاذ»: تسجيل الغياب و«لا أحد» يُحفظان وتُرسَلان تلقائيا).

## قائمة التعويض (للمتغيبين وفريق الدعم)

زر «📚 قائمة التعويض» في أعلى الصفحة يعرض التلاميذ المتغيبين والمواد التي فاتتهم، ليبرمج فريق الدعم والتقوية حصص التعويض:

- **حسب المادة**: لكل مادة جدول بأسماء المتغيبين (مع الأستاذ، القسم، عدد الساعات، والحصص الفائتة بتاريخها)، **وحسب التلميذ**: لكل تلميذ مجموع ساعاته والمواد التي فاتته.
- الفترة: هذا الأسبوع، الأسبوع الماضي، هذا الشهر، الشهر الماضي، كل الفترة المسجّلة، أو فترة مخصّصة. وللتصفية: القسم، المستوى، المادة، والحد الأدنى لساعات الغياب.
- طباعة بأعمدة فارغة «موعد التعويض» و«ملاحظات» تُملأ بخط اليد، وتصدير إلى إكسيل (ورقتان: حسب المادة وحسب التلميذ).
- زر «📲 إبلاغ الأولياء» (في كل مادة، أو أمام كل تلميذ في عرض «حسب التلميذ») يفتح نافذة لتحديد **تاريخ حصة التعويض وساعتها ومكانها**، ثم يفتح واتساب برسالة جاهزة لكل ولي أمر (رقمه مأخوذ من الجدول). لا يُحفظ شيء في الخادم، لذلك يعمل أيضا بحساب الاطلاع.
- يمكن لمنسق الدعم أن يستعملها بحساب **اطلاع** (للقراءة فقط) دون أي صلاحية تعديل.
- المادة والأستاذ لكل حصة يُحفظان الآن في سجل الأسابيع (`subj` و`tch` في `api/_stats.js`). الأسابيع التي أُرشفت قبل هذا التحديث تعتمد على جدول المواد الحالي ويُنبَّه إلى ذلك أسفل القائمة؛ ولا يُحتسب إلا التلاميذ الموجودون حاليا في القسم.

## إشعار ولي الأمر والاستدعاء (شبه آلي عبر واتساب)

> إرسال إشعارات الغياب والاستدعاءات لأولياء الأمور (اللوحتان في أسفل الجدول) **للمسؤول وحده**؛ حسابات الاطلاع لا ترى هاتين اللوحتين ولا أزرار الإرسال.

- يحسب التطبيق ساعات غياب كل تلميذ **تراكميًا خلال الشهر الميلادي الجاري** (الأسابيع المؤرشفة في `/api/history` + الورقة المعروضة). كل خانة غياب = ساعة.
- **ساعة واحدة** ← «إشعار بالغياب»؛ **ثلاث ساعات فأكثر** ← «استدعاء للحضور» لمعالجة وضعية الغياب (الحدّان `NT_NOTICE` و`NT_SUMMONS` في `index.html`).
- لوحة «إشعارات تلقائية» تسرد الحالات المعلّقة في كل الأقسام، والرسالة جاهزة؛ زر «إرسال» يفتح واتساب برقم ولي الأمر (عمود «هاتف ولي الأمر»)، وزر «تم» يعلّمها معالَجة دون إرسال.
- بعد تأكيد تسجيل غياب يقترح التطبيق الإرسال فورًا عند بلوغ حدّ جديد (مرة واحدة لكل تلميذ ونوع رسالة في الجلسة).
- ما أُرسل محفوظ في `state.notices[YYYY-MM]["القسم|الاسم"]` فلا يتكرر الإشعار نفسه ولو فُتح التطبيق من جهاز آخر. يقتصر الإرسال والتعليم على حساب المسؤول.
- الإرسال التلقائي بلا نقرة غير ممكن بواتساب العادي؛ يتطلب خدمة مراسلة مدفوعة (SMS أو WhatsApp Business API).
- الأسابيع المؤرشفة قبل هذه الميزة لا تتضمن أسماء الغائبين، فلا تدخل في حساب الشهر.

## منع تسجيل غياب حصة لم يحن وقتها

- لا يقبل التطبيق تسجيل غياب في حصة تاريخها أو ساعة بدايتها لم تأتِ بعد (حسب تاريخ «من» للأسبوع وساعة الجهاز)؛ تظهر هذه الخانات بنقش رمادي وتُرفض بنقرة مع رسالة توضّح الموعد. حذف غياب سُجّل خطأً يبقى ممكنًا.
- بداية الحصص الافتراضية: صباحا 08:00 · 09:00 · 10:00، مساء 14:00 · 15:00 · 16:00، ويعدّلها المسؤول بزر «⏰ توقيت الحصص» **لكل قسم على حدة**: التوقيت المضبوط يخص القسم المعروض فقط (يُحفظ في `state.data[قسم].times`)، والقسم الذي لم يُضبط توقيته يتبع التوقيت الافتراضي (`state.periodTimes`). عند إضافة حصة أو حذفها تُعاد مواءمة توقيت كل قسم معها.
- إن لم يُحدَّد تاريخ «من» للأسبوع فلا يمكن معرفة موعد الحصص، فلا يُطبَّق المنع.
- المنع على مستوى واجهة التطبيق (حساب المسؤول)، ولا يفحصه الخادم.

## استيراد التنظيم التربوي (المادة والأستاذ لكل قسم من إكسيل)

- زر «📅 استيراد التنظيم التربوي» (للمسؤول، في شريط الأدوات) يملأ **اسم المادة واسم الأستاذ في كل حصة من كل قسم** انطلاقا من ملف إكسيل «التنظيم التربوي» بدل كتابتها يدويا.
- يقرأ التطبيق من الملف: (1) كتلة لكل أستاذ فيها «مادة : …» واسم الأستاذ فوقها ورمز قصير تحتها (FR1، M2، …) ← رمز = أستاذ + مادة؛ (2) جدول الأقسام (أيام الأسبوع، الساعات «9 - 8»، وفي كل سطر قسم ورموز حصصه)؛ (3) إن وُجدت أوراق «استعمال الزمن لقسم …» فتُستعمل لتصحيح كتابة المادة ولحصص بلا رمز أستاذ واحد (مثل «أنشطة / اللغة العربية» و«أنشطة - دعم وتقوية»). الصباح والمساء يُفرَّقان بالساعة (قبل 13 صباحا)، وتُوزَّع الحصص على أعمدة الجدول حسب عدد الحصص الحالي.
- تظهر نافذة بأقسام الملف: لكل قسم تختارون القسم الذي يُطبَّق عليه (يُقترح القسم المطابق في الاسم، وإلا «إنشاء قسم جديد»)، أو تتجاهلونه. يُستبدل اسم المادة والأستاذ في الأقسام المحددة (وتُفرَّغ الحصص الفارغة في الملف)، ولا تتغير لوائح التلاميذ ولا الغياب. لا يمكن تطبيق قسمين من الملف على القسم نفسه.
- يعمل بقارئ إكسيل الذي يُحمَّل من الإنترنت (نفس قارئ استيراد لائحة التلاميذ).

## الموسم الدراسي وأرشفة الغياب السنوي

- يظهر الموسم الدراسي (مثال «الموسم الدراسي 2026/2027») في أعلى الصفحة تحت عنوان التطبيق. إن لم يُضبط يُستنتج من تاريخ الأسبوع على الجدول (شهر غشت وما بعده يبدأ موسما جديدا). للمسؤول أن يعدّله بالضغط عليه (`state.season`).
- زر «🗄️ أرشفة الموسم» (للمسؤول، تحت الجدول بجانب «إضافة تلميذ» و«استيراد لائحة») ينقل غياب **كل أسابيع الموسم** إلى أرشيف الموسم على الخادم (`PREFIX:season:2026-2027` مع فهرس `PREFIX:seasons`)، ثم يفرّغ سجل الإحصائيات ويمسح الغياب من الجدول ويمحو تواريخ الأسبوع، ويبدأ الموسم التالي (2027/2028). تبقى لوائح التلاميذ والأقسام والمواد والتوقيت كما هي. العملية لا يمكن التراجع عنها بعد المسح، ولا تتم إلا بعد حفظ الجدول بنجاح على الخادم وتتطلب اتصالا بالإنترنت.
- لا يمكن أرشفة موسم دون أسابيع مسجّلة، ولا أرشفة نفس الموسم مرتين.
- في «الإحصائيات» تظهر قائمة «الموسم» بمجرد وجود موسم مؤرشف: الموسم الجاري أو أحد المواسم المؤرشفة. الموسم المؤرشف للاطلاع والطباعة والتصدير إلى إكسيل فقط (كل أنواع العرض: يومي وأسبوعي وشهري وحسب الأقسام والمستويات والتلاميذ)، ويظهر الموسم في رأس الطباعة وملف إكسيل. يستطيع المسؤول وحده حذف موسم مؤرشف نهائيا.
- الواجهة الفرنسية: «Année scolaire 2026/2027» و«Archiver l'année».

## الرجوع إلى الأسبوع الماضي (تصحيح غياب سُجّل بالخطأ)

- زر «⏪ السابق» في شريط الأدوات (للمسؤول) يعرض الأسبوع السابق في الجدول ليُصحَّح؛ وعند حفظ التعديل يُحدَّث ملخص ذلك الأسبوع في سجل الإحصائيات تلقائيًا. يظهر شريط أصفر يذكّر بأنكم في الأسبوع الماضي، ويُفعَّل زر «📍 الأسبوع الجاري» (على سطر التاريخ، قبل خانتي «من» و«إلى») للعودة، بينما يُعطَّل «السابق».
- عند «التالي» يُحفظ الأسبوع المنتهي كاملا (الغياب والمواد والأساتذة) في `state.other`، فيرجع كما كان. قبل أول «التالي» يُبنى الأسبوع الماضي من سجل الإحصائيات (التلاميذ الغائبون فقط)، ولا يتوفر ذلك للأسابيع المؤرشفة قبل ميزة الإحصاء حسب التلميذ.
- لا يمكن الانتقال إلى «التالي» وأنتم تعرضون الأسبوع السابق.
- **تغيير تاريخ «من» يعرض بيانات ذلك الأسبوع:** عند كتابة تاريخ أسبوع آخر في خانة «من» والضغط على Enter (للمسؤول) يُحفظ الأسبوع الحالي ويُعرض الأسبوع المختار بغيابه ومواده وأساتذته (من الأسبوع المحفوظ في الجدول أو من سجل الإحصائيات). فإن لم تكن له بيانات سأل التطبيق: عرض أسبوع فارغ، أو تغيير التاريخ فقط، أو إلغاء. وتاريخ في الأسبوع نفسه يغيّر التسمية فقط. أسبوع العطلة يُفتح مقفلا، والأسبوع المستقبلي الفارغ لا يدخل أرشيف الإحصائيات.

## صفّ الأيام ثابت أثناء التمرير

- الجدول يتمرّر داخل إطاره (بارتفاع أقصاه نحو 82% من الشاشة) فيبقى صفّا «أيام الأسبوع» و«الحصص» ظاهرين أعلاه كلما نزلتم في لائحة التلاميذ.
- يتكرّر الصفّان أيضًا أسفل اللائحة (بعد سطر مجموع الغياب في الحصة).

## عدد الحصص صباحا ومساء (إضافة حصة أو حذفها)

زر «🧮 عدد الحصص» (للمشرف فقط) يضبط عدد الحصص في اليوم ليلائم النظام الدراسي للمؤسسة: من 0 إلى 8 حصص صباحا ومثلها مساء (يجب أن تبقى فترة واحدة على الأقل، فيمكن لمؤسسة تدرّس صباحا فقط أن تحذف كل الحصص المسائية). الافتراضي 3 + 3 كما كان.

- **إضافة** حصة تُضاف في آخر الفترة (ح4 مثلا) لكل أيام الأسبوع وكل الأقسام، وتُعطى توقيتا افتراضيا بعد الحصة السابقة بساعة (يُعدَّل من «⏰ توقيت الحصص»).
- **حذف** حصة يسأل عن رقمها ويطلب التأكيد مع ذكر عدد ساعات الغياب المسجلة فيها؛ الحصص التي بعدها يتغيّر ترقيمها وتبقى موادها وأساتذتها وغياباتها مع حصصها الصحيحة.
- التغيير يُطبَّق على الأسبوع المعروض وعلى «الأسبوع الماضي» المحفوظ في الجدول؛ الأسابيع المؤرشفة في الإحصائيات تحتفظ بتخطيطها الخاص (يُخزَّن `pc` مع كل ملخّص أسبوع) فتبقى أرقامها صحيحة ولا تتغير.
- التخزين: `state.pc = [صباحا, مساء]` ضمن حالة الجدول نفسها، فكل مشروع Vercel له إعداداته الخاصة (مدرسة ابتدائية بنظام مختلف عن الإعدادية) من نفس الكود.

## تغيير شعار المؤسسة

زر «🖼️ شعار المؤسسة» (أو النقر على الشعار نفسه) للمسؤول فقط: يختار صورة من جهازه (png أو jpg أو webp)، فتظهر له معاينة، ثم «حفظ الشعار».

- تُصغَّر الصورة في المتصفح إلى 320 بكسل كحد أقصى (ويحافظ png على الشفافية) فيبقى حجمها صغيرا.
- يُحفظ الشعار على الخادم (مفتاح `<KEY_PREFIX>:logo` في Redis، عبر `POST /api/config` للمسؤول وحده، مع فحص النوع والحجم)، فيظهر لدى كل المستخدمين وفي الطباعة، ولا يتأثر بإعادة النشر.
- الأجهزة الأخرى تلتقط التغيير خلال ثوان (يُحفظ `state.logoV` مع الجدول فيُعاد جلب الشعار).
- «استرجاع الشعار الأصلي» يحذفه ليعود `LOGO_FILE` إن وُجد، وإلا الشعار الافتراضي.
- الشعار المستطيل يظهر بإطار مستطيل تلقائيا، والمربع بإطار دائري.

## موافقة المسؤول على حسابات الاطلاع

إنشاء حساب جديد من صفحة الدخول لم يعد يفتح الدخول مباشرة؛ يصبح **طلبا** ينتظر موافقة المسؤول:

- بعد «إنشاء الحساب» تظهر رسالة «تم إرسال طلبكم إلى المسؤول» ولا تُصدر جلسة. محاولة الدخول قبل القبول تعطي «حسابكم في انتظار موافقة المسؤول» (بعد التحقق من كلمة المرور، فلا يُكشف شيء لمن لا يعرفها).
- زر «👥 الموافقة على حساب جديد» (للمسؤول فقط) يعرض عدد الطلبات المعلّقة (يُحدَّث كل دقيقة)، وفي نافذته: **قبول** أو **رفض** لكل طلب، وقائمة الحسابات المقبولة مع **إزالة**.
- الإزالة تُسقط الدخول فورا وتُبطل الجلسة الحالية لذلك الحساب خلال دقيقة (يُتحقق من أن الحساب ما زال مقبولا في `/api/state` و`/api/history` و`GET /api/auth`، ونتيجة التحقق تُخزَّن دقيقة في ذاكرة الدالة).
- واجهة الخادم: `api/users.js` (للمسؤول فقط): `GET` (و`?all=1` لإضافة الحسابات المقبولة) و`POST {action:'approve'|'reject'|'remove', email}`. يُخزَّن الطلب في المفتاح `<KEY_PREFIX>:user:<email>` بحالة `status:'pending'`، وفهرس الطلبات في `<KEY_PREFIX>:pending`، ويُرفض الطلب الجديد إن بلغ المعلّق 200 طلب.
- الحسابات التي أُنشئت قبل هذه الميزة (بلا حقل `status`) تُعتبر مقبولة وتبقى تعمل كما هي.

## دعوة الأساتذة بالبريد (حساب جاهز بنقرة على الرابط)

الأساتذة لا يمرّون بطلب الموافقة: يدعوهم المسؤول ببريدهم، فيصل كل أستاذ(ة) رابط، وبمجرد فتحه واختيار كلمة مرور يصبح حسابه **أستاذا مقبولا** ويدخل مباشرة إلى شاشة النداء. أما زر «👥 الموافقة على حساب جديد» فيبقى لمن سجّل حسابا بنفسه من صفحة الدخول (شخص غير معروف).

- **من النافذة**: «👥 الموافقة على حساب جديد» ← خانة «دعوة أساتذة»: سطر لكل أستاذ(ة)، البريد ثم الاسم كما في الجدول (اختياري، وبه لا يسجّل الحساب إلا في حصصه). تُقبل عدة أسطر دفعة واحدة، وتُهمَل البريدات المكررة.
- **الرابط**: عشوائي (192 بتا)، صالح **7 أيام** و**يُستعمل مرة واحدة**؛ لا يُخزَّن في قاعدة البيانات إلا ناتج SHA-256 له. إعادة الإرسال تُبطل الرابط القديم وتصدر جديدا، و«إلغاء» يوقف الدعوة.
- **الأستاذ(ة)**: يفتح الرابط فتظهر صفحة «تفعيل حساب الأستاذ(ة)» ببريده مثبَّتا، فيكتب كلمة مرور (8 أحرف فأكثر) مرتين ويضغط «تفعيل حسابي» فيدخل مباشرة. لو فتح الرابط مرة ثانية أو بعد انتهائه ظهرت صفحة الدخول العادية مع شرح السبب.
- **إن لم يُضبط البريد في الخادم** (أو فشل الإرسال) تظهر للمسؤول الرابط نفسه مع «نسخ الرابط» و«📲 واتساب» ليرسله بنفسه؛ فالميزة تعمل دائما، والبريد تسهيل فقط.
- **أمان**: بريد الدعوة هو الذي يُثبت ملكية الصندوق. لذلك تُحذف عند الدعوة أي «طلب حساب» سجّله شخص آخر بالبريد نفسه (لم يثبت أنه صاحبه)، وإن سجّل أحدهم بعد إرسال الدعوة فكلمة مرور صاحب الرابط هي التي تُعتمد. ولا يستطيع الرابط تغيير كلمة مرور حساب مقبول من قبل (يُرجع «لهذا البريد حساب مفعّل بالفعل»). وإن كان البريد لحساب مقبول أصلا فتُحوّله الدعوة إلى أستاذ مباشرة دون رابط. حدّ الدعوات المعلّقة 200، ومحاولات صفحة الدعوة والتفعيل محدودة لكل عنوان IP.
- **الخادم**: `GET /api/auth?invite=<رمز>` (بريد الدعوة واسمها فقط)، و`POST /api/auth {action:'accept', token, password}`، و`POST /api/users {action:'invite'|'uninvite', email, teacher}` وقائمة الدعوات في `GET /api/users?all=1` (`invites` و`mail`). المفاتيح: `<KEY_PREFIX>:inv:<hash>` (7 أيام) و`<KEY_PREFIX>:invites` (فهرس المسؤول).

### إعداد إرسال البريد (مرة واحدة، اختياري)

يرسل الخادم عبر أي حساب SMTP (`api/_mail.js`، دون مكتبات). أبسط طريقة بحساب Gmail:

1. فعّلوا «التحقق بخطوتين» في حساب Google، ثم أنشئوا «كلمة مرور تطبيق» من `myaccount.google.com/apppasswords` (16 حرفا).
2. في Vercel ← المشروع ← **Settings → Environment Variables** أضيفوا ثم أعيدوا النشر:

| الاسم | القيمة |
|---|---|
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_USER` | عنوان Gmail كاملا |
| `SMTP_PASS` | كلمة مرور التطبيق (16 حرفا؛ مع Gmail تُتجاهل المسافات تلقائيا). تنبيه: الاسم `SMTP_PASS` وليس `SMPT_PASS` |
| `SMTP_PORT` | `465` (الافتراضي؛ التشفير الكامل) أو `587` (STARTTLS) |
| `SMTP_FROM` | اختياري: اسم المُرسِل، مثال `"مؤسسة المثابرة" <school@gmail.com>` |
| `PUBLIC_URL` | اختياري: عنوان الموقع الثابت، مثال `https://ghiyab-app.vercel.app`، إن أردتم رابطا لا يتغيّر مع عنوان الطلب |

- لا تُرسَل كلمة المرور على اتصال غير مشفَّر أبدا: إن لم يعرض الخادم STARTTLS على المنفذ غير المشفَّر رُفض الإرسال (`SMTP_ALLOW_PLAIN=1` لمرحّل داخلي موثوق فقط).
- حدّ Gmail نحو 500 رسالة يوميا. قد تصل الرسائل الأولى إلى «الرسائل غير المرغوب فيها»، فاطلبوا من الأساتذة البحث عنها هناك.
- `INSTITUTION_NAME` (إن وُجد) يظهر في نص الرسالة.

## حساب «أستاذ»: تسجيل الغياب عند النداء

يمكن للمسؤول أن يمنح حسابا مقبولا صلاحية **تسجيل الغياب فقط**: الطريق المعتاد هو **دعوة الأستاذ(ة) ببريده** (القسم السابق)، أو من زر «👥 الموافقة على حساب جديد» ← قائمة «الحسابات المقبولة» ← «جعله أستاذا» لحساب موجود؛ و«إرجاعه إلى اطلاع فقط» يسحبها فورا:

- الأستاذ يرى الورقة كحساب الاطلاع، وتصير خانات الغياب قابلة للنقر **في حصص اليوم التي بدأ وقتها فقط**: نقرة واحدة تسجّل غيابا غير مبرر (دون أسئلة حتى يكون النداء سريعا)، والنقر على غياب سجّله يطلب تأكيد الحذف. لا يرى بقية أزرار التعديل.
- حقل «اسم الأستاذ(ة) كما في الجدول» اختياري: إن كُتب فلا يسجّل الحساب إلا في الحصص التي يحمل حقل «الأستاذ(ة)» فيها هذا الاسم (مقارنة كلمة بكلمة دون اعتبار الترتيب: «نعيمة بداوي» = «بداوي نعيمة» = «ذ. نعيمة بداوي»، وتتجاهل الفراغات والنقط والتشكيل وفروق الألف والياء والتاء المربوطة وحركات الحروف اللاتينية). وإن تُرك فارغا سُجّل في أي حصة من اليوم. وإن كُتب اسم لا يطابق أي حصة في الجدول فلن يستطيع الحساب التسجيل في أي حصة (تظهر له رسالة «هذه الحصة ليست من حصصكم»)، فاحرصوا على كتابته كما في الجدول أو اتركوه فارغا.
- **الخادم هو الذي يفرض القواعد** عبر `POST /api/mark {cls, si, name, ci, value}` (`api/mark.js`)، ولا تُغني عنها الواجهة: الأسبوع يجب أن يكون **الأسبوع الجاري** (الذي يضم تاريخ اليوم) وليس أسبوع عطلة، والعمود من **يوم اليوم** بتوقيت الدار البيضاء، والحصة بدأ وقتها (أوقات القسم أو المشتركة أو الافتراضية) و**لم تنتهِ بعد**، وإن وُجد اسم أستاذ فيجب أن يطابق. الغياب المبرر («م») قرار المسؤول: لا ينشئه الأستاذ ولا يزيله. والاسم المرسل يجب أن يطابق التلميذ في الموضع `si` فلا يُسجَّل على تلميذ آخر إن تغيّرت اللائحة.
- **شريط الأيام (على الحاسوب)**: فوق الجدول العريض أزرار الاثنين … الجمعة؛ النقر على يوم يُزلق الجدول أفقيا حتى يصبح أول عمود من ذلك اليوم بجانب أعمدة الرقم والاسم والهاتف الثابتة، ويُميَّز اليوم الحالي. ويعمل بالعربية والفرنسية (الاتجاه من اليسار إلى اليمين)، وأعمدة الرقم والاسم والهاتف تبقى ثابتة في الفرنسية أيضا.
- **الجدول على الهاتف (عرض ≤ 700 بكسل)**: تُرصّ أيام الأسبوع واحدا تحت الآخر ويُنتقل بينها بالتمرير العمودي (مع شريط أيام في الأعلى يقفز إلى اليوم المطلوب ويُميّز اليوم الحالي)، فلا حاجة إلى التمرير الأفقي. لكل يوم جدوله (رقم واسم وحصص الصباح والمساء)، ومواده وأساتذته داخل «المواد والأساتذة»، ثم في الآخر «لائحة التلاميذ وهواتف أولياء الأمور» (للمسؤول والمطّلع). خانة الغياب نحو 34–37 بكسل عرضا و41 ارتفاعا وعمود الاسم 72 بكسل (يتّسع الجدول بست حصص لشاشة 360 بكسل دون تمرير أفقي). الشاشات الأوسع تبقى على الجدول العريض المعتاد.
- **واجهة مبسّطة للأستاذ (خاصة بالهاتف)**: لا يظهر له إلا الموسم الدراسي، وتاريخ الأسبوع، وشريط الأقسام، وجدول القسم مع لائحة أسمائه (رقم واسم فقط)، وزر «إضافة تلميذ»، وتبديل اللغة، والخروج. وتُخفى عنه الإحصائيات والطباعة وقائمة التعويض والاستيراد والموافقة على الحسابات والشعار وبدء أسبوع جديد وإشعارات أولياء الأمور وأرشفة الموسم وأعمدة الهواتف والحذف. يضيف التلميذ باسمه فقط (`POST /api/mark {action:'addstudent', cls, name}`: يرفض الخادم الاسم المكرر والفارغ، ولا يضيف هاتفا)، ولا يحذف ولا يعدّل اسما.
- أرقام هواتف أولياء الأمور لا يرسلها الخادم للأستاذ أصلا: `GET /api/state` يعيدها فارغة لحسابه.
- **الأسبوع الجاري لا يتأثر بتنقّل المسؤول**: حين يعرض المسؤول أسبوعا ماضيا أو قادما (أزرار «السابق» و«الأسبوع الجاري» أو كتابة تاريخ «من») تتبدّل الورقة المشتركة ويُحفظ الأسبوع الجاري جانبا في `state.other`. الأستاذ وحسابات الاطلاع لا يتبعون ذلك: تعرض لهم الصفحة دائما الأسبوع الذي يضم تاريخ اليوم (`liveView` في `index.html`، بنسخة محلية لا تُكتب)، وتسجيل الأستاذ يذهب إلى ذلك الأسبوع نفسه في الخادم أينما كان محفوظا (`frameFor` في `api/mark.js`، مع تحويل رقم الحصة إن اختلف عدد الحصص). يطّلع الأستاذ على غياب أيام الأسبوع الجاري كلها، ولا يسجّل إلا في حصص اليوم.
- **نهاية الحصة**: بعد انتهاء حصته لا يسجّل الأستاذ غيابا ولا «لا أحد» ولا يعدّل ولا يحذف (يصحّح المسؤول عند الحاجة). نهاية الحصة = بدايتها + ساعة (`PERIOD_MIN` في `api/mark.js` و`index.html`)، أو بداية الحصة التالية في الفترة نفسها إن كانت أسبق. العبرة بوقت النقرة `at` لا بوقت الوصول، فنقرة سُجّلت داخل الحصة دون إنترنت تُقبل لاحقا (في حدود 18 ساعة).
- لا يملك الأستاذ كتابة الورقة كاملة: `POST /api/state` يبقى للمسؤول وحده (يرجع 403). التعديل يمسّ خانة واحدة فقط، فلا يُمحى شيء من عمل المسؤول.
- يُقفل الخادم (`withLock`، مفتاح `<KEY_PREFIX>:lock:state`) حول قراءة الورقة وكتابتها، فلا يضيع نداءان متزامنان لأستاذين، ولا يضيع النداء أثناء حفظ المسؤول للورقة.
- الدور يُخزَّن في سجل الحساب (`role:'teacher'` و`teacher:'<الاسم>'`) ويغلب على ما في الرمز، فتغييره يسري خلال دقيقة دون إعادة دخول. إشعارات أولياء الأمور تبقى للمسؤول وحده.
- **عندما لا تستجيب الخانة**: النقر على خانة مقفلة يعرض للأستاذ سببها بدل الصمت: اليوم عطلة نهاية الأسبوع، أو الورقة ما زالت على أسبوع سابق (على المسؤول أن يضغط «التالي» ليبدأ الأسبوع الجديد، وإلا لا يستطيع أي أستاذ التسجيل)، أو الخانة من يوم آخر، أو الحصة لم يبدأ وقتها، أو الحصة لأستاذ آخر (مع عرض الاسم المكتوب في الجدول واسم الحساب)، أو الغياب مبرَّر.
- **زر «لا أحد»**: إن لم يتغيب أي تلميذ في حصة، يضغط الأستاذ(ة) زر «لا أحد» الظاهر أسفل عمود حصته (في صف «عدد الغياب في الحصة»)، فيُسجَّل في الورقة أن النداء تمّ وأن لا غائب (مع اسم الأستاذ والساعة). ويمكنه إلغاؤه بنقرة وتأكيد. وهناك زر ثانٍ «✅ لا أحد» في شريط «إضافة تلميذ» (بعد زر الإضافة مباشرة) يخص حصته الجارية في القسم المعروض ويطلب تأكيدا يذكر القسم والحصة؛ وللمسؤول زر «✅ متابعة النداء» بعد «📥 استيراد لائحة من إكسيل». الخادم يفرض القواعد نفسها: `POST /api/mark {action:'called', cls, ci, value}` يطلب أن تكون الحصة من اليوم وقد بدأت وأن تكون حصة هذا الأستاذ، ويُرفض (409) إن كان في الحصة غياب مسجَّل؛ وتسجيل غياب بعد ذلك في الحصة نفسها يُلغي «لا أحد» تلقائيا. يُخزَّن في `columns[i].called = {at, by}` ويُمحى مع بدء أسبوع جديد (ويبقى محفوظا في «الأسبوع الماضي»).
- **متابعة الإدارة**: تحت عدد الغياب في كل حصة تظهر للمسؤول وللاطلاع علامة ✓ (تم النداء بـ«لا أحد»؛ ومرور الفأرة يعرض الأستاذ والساعة) أو علامة حمراء «!» (لا غياب ولا «لا أحد» بعد 20 دقيقة من بداية الحصة). زر «✅ متابعة النداء» يفتح قائمة الحصص بلا نداء مسجَّل (القسم، الحصة، المادة، الأستاذ) وقائمة تصريحات «لا أحد» بساعتها، لليوم أو لكل الأسبوع. الفحص يخص الأسبوع الجاري وحصص المواد المعبَّأة فقط. ملاحظة: في أسبوع تفعيل الميزة تظهر «!» لحصص الأيام السابقة لأنها لم تعرف الزر بعد.
- **العمل دون إنترنت**: يستمر الأستاذ في تسجيل الغياب وفي الضغط على «لا أحد» عند انقطاع الإنترنت. كل نقرة تُحفظ على الجهاز (المفتاح `ghiyab_tq`) وتظهر فورا بإطار متقطع برتقالي («في الانتظار»)، ويصبح الشريط «🟠 دون اتصال… (N في الانتظار)»، ثم **تُرسَل بالترتيب تلقائيا** عند عودة الاتصال (الشريط 🟢) دون أي تدخل. الشروط: أن يكون الأستاذ قد سجّل الدخول على هذا الجهاز مرة واحدة وهو متصل (يحفظ الجهاز حسابه واسمه وآخر ورقة)، فيُفتح التطبيق بعدها دون إنترنت؛ ولا يمكن تسجيل الدخول لأول مرة دون إنترنت. التسجيلات المؤجلة تحمل وقت النقر `at` فيفحص الخادم قواعد «حصة اليوم» و«بدأ وقتها» على ذلك الوقت لا على وقت الوصول، ولا يقبل وقتا في المستقبل ولا أقدم من **18 ساعة**. ما رفضه الخادم عند وصوله (مثلا غياب بُرِّر في الأثناء، أو بدأ أسبوع جديد، أو غادر التلميذ اللائحة) تظهر للأستاذ رسالة تذكره بالتلميذ والحصة والسبب، وتعود الشاشة إلى ما في الخادم. وإن انتهت صلاحية الدخول ظلّت التسجيلات محفوظة وأُرسلت بعد تسجيل الدخول بالحساب نفسه؛ وزر «خروج» يحذّر إن كانت هناك تسجيلات لم تُرسَل. إضافة تلميذ جديد تحتاج إنترنت.

## استيراد لائحة التلاميذ دون ضياع الغياب والهواتف

نافذة «📥 استيراد لائحة من إكسيل» فيها ثلاثة أزرار:

- **تحديث اللائحة مع الاحتفاظ بالغياب والهواتف** (الأول، والمستحسن): يطابق أسماء الملف مع التلاميذ الموجودين كلمة بكلمة دون اعتبار الترتيب ولا فروق الألف والياء والتاء المربوطة، ويطابق حتى الاسم الذي يختلف بحرف أو حرفين إن لم يلتبس بغيره (تُعرض الأسماء المتشابهة في الملخص). من وُجد في الاثنين يحتفظ بغيابه وهاتفه، ويُضاف الجدد فارغين، ويُرتَّب الجدول بترتيب الملف. أما الموجودون في اللائحة وغير موجودين في الملف فيسأل التطبيق: «حذف غير الموجودين» أو «إبقاؤهم في آخر اللائحة».
- **إضافة إلى اللائحة الحالية**: لا تُكرّر اسما موجودا (كان يكرّره من قبل).
- **استبدال اللائحة (يمسح الغياب والهواتف)**: لا يعمل إلا بعد تأكيد صريح يذكر عدد الغيابات والهواتف التي ستُمسح (هذا الزر وحده هو الذي ضيّع البيانات عندما استُعمل مع لائحة هي نفسها تقريبا).

## النسخ الاحتياطية واسترجاع الغياب والهواتف

- يحفظ الخادم **نسخة من الورقة تلقائيا قبل أي حفظ يُضيّع دفعة واحدة** 3 غيابات أو أكثر، أو هاتفين أو أكثر، أو تلميذين أو أكثر (استبدال اللائحة، الحذف الجماعي، بدء أسبوع جديد...)، وكل 12 ساعة على الأكثر. يُحتفظ بآخر 15 نسخة (`<KEY_PREFIX>:bk:<وقت>` وفهرسها `<KEY_PREFIX>:bk:index` في Redis). لا يمنع أي خلل في النسخ الحفظَ نفسه.
- زر «🕘 النسخ الاحتياطية» (للمسؤول): يعرض الورقة الآن وقائمة النسخ (التاريخ، سبب النسخة، عدد التلاميذ والغيابات والهواتف)، ويتيح «حفظ نسخة الآن» و:
  - **الاسترجاع الجزئي**: يعيد لتلاميذ اللائحة الحالية هواتفهم (حيث الخانة فارغة) وغيابهم (إن كان الأسبوع نفسه)، مطابقا بالاسم، دون المساس بما سواهم.
  - **الاسترجاع الكامل**: يعيد الورقة كلها كما كانت.
  - كلاهما يحفظ نسخة من الحالة الحالية قبل التنفيذ، فيمكن التراجع عنه.
- واجهة الخادم `api/backups.js` (للمسؤول وحده): `GET` للقائمة، و`POST {action:'snapshot'}` و`POST {action:'restore', ts, mode:'merge'|'full'}`، والمنطق في `api/_backup.js`.
- ما كان قبل إضافة هذه الميزة لا نسخة له من التطبيق. وإن كان في Upstash «Daily Backup» مفعّلا فقد توجد نسخة هناك (لوحة قاعدة البيانات ← Backups).

## النسخة الفرنسية (تبديل اللغة داخل التطبيق نفسه)
- زر **Français / العربية** في صفحة الدخول وفي أعلى الصفحة يبدّل لغة الواجهة؛ تُحفظ اللغة المختارة في المتصفح لكل جهاز. البيانات والحسابات هي نفسها في اللغتين.
- العنوانان الجديدان `etablissement-secondaire.vercel.app` و`etablissement-primaire.vercel.app` يُفتحان بالفرنسية أول مرة، ويمكن الرجوع إلى العربية بالزر. ويمكن فرض اللغة برابط مثل `?lang=fr` أو `?lang=ar`.
- عند اختيار الفرنسية تتحول الصفحة إلى اتجاه اليسار لليمين، وتتبع اللغةَ كلٌّ من: رسائل واتساب (إشعار ولي الأمر والاستدعاء)، وورقة الغياب المطبوعة، وطباعة الإحصائيات، والمبيانات (وصورة PNG)، وملف إكسيل المُصدَّر. وفي استيراد لائحة إكسيل يُتعرَّف أيضا على عناوين أعمدة فرنسية مثل Nom وPrénom وÉlève.
- الترجمة كلها في ملف واحد `fr.js` (قاموس + أنماط جمل + مراقب للصفحة)، فلا يتأثر الوضع العربي بشيء. لتعديل صياغة فرنسية افتحوا `fr.js` وابحثوا عن النص العربي في `EXACT` أو `SENT`.
- أسماء التلاميذ والأقسام والمواد والأساتذة تبقى كما كُتبت. القسم الافتراضي «القسم 1» يظهر بالفرنسية `Classe 1`.
- اسم المؤسسة: «مؤسسة المثابرة الخاصة» و«مدرسة المثابرة الخاصة_ابتدائي» لهما ترجمة جاهزة. ولأي اسم آخر اضغطوا ✏️ بجانب الاسم وأنتم في الواجهة الفرنسية لكتابة الاسم الفرنسي؛ يُحفظ وحده (`instNameFr`) دون المساس بالاسم العربي.

## التبرير
كل غياب إما غير مبرر (`true`، «غ» أحمر) أو مبرر (`'j'`، «غ» + «م» أخضر). يُختار عند التسجيل ويمكن تحويله بالنقر على الخانة. في ملخص الأسبوع (`api/_stats.js`) يُرمَّز كل حصة بـ 0 حاضر / 1 غائب / 2 غياب مبرر. ويحمل الملخص أيضا `colsJ` (عدد المبرر لكل حصة)، وتعرضه الإحصائيات في عمودين «منها مبررة / منها غير مبررة» وفي البطاقات الرئيسية.

## العطل البينية
قائمة `state.breaks` (`from` / `to` / `label`، والافتراضي 19–23 أكتوبر 2026) تحدّد أسابيع مقفلة: تُعرض فيها كتل «عطلة بينية» بدل الخانات ولا تدخل الإحصائيات (`DEFAULT_BREAKS` في `index.html` و`api/_stats.js`).

## سجل التطوير
`docs/app-journal.pdf` يلخّص مراحل بناء التطبيق وتطويره (وله نسختان: بالفرنسية `docs/app-journal-fr.pdf` وبالإنجليزية `docs/app-journal-en.pdf`، من ترجمتي `docs/journal.fr.json` و`docs/journal.en.json`). مصدره `docs/journal.json`، ويُولَّد بالأمر `node docs/build-journal.js` (يتطلب playwright)، ويُحيَّن مع كل إضافة جديدة.

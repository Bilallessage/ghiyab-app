# ورقة ضبط غياب التلاميذ — نسخة Vercel (استضافة سحابية دائمة)

هذه نسخة من التطبيق مُعدّة للنشر على Vercel، بحيث يحصل التطبيق على رابط عام دائم
تفتحه كل المكاتب في نفس الوقت، والبيانات تُحفظ وتتشارك تلقائيًا بينها، دون أي
حاجة لتشغيل حاسوب كخادم (لا حاجة لملف server.py ولا لبقاء أي جهاز مفتوحًا).

## محتويات المجلد

- `index.html` — واجهة التطبيق (شاشة الدخول + الجدول).
- `api/auth.js` — الدخول وإنشاء الحسابات (المسؤول / حسابات الاطلاع).
- `api/state.js` — قراءة وحفظ بيانات الغياب؛ القراءة لأي حساب، والكتابة للمسؤول فقط.
- `api/history.js` — مصدر صفحة الإحصائيات (يومي / أسبوعي / شهري).
- `api/_lib.js` و`api/_seed.js` و`api/_stats.js` — ملفات مساعدة للخادم (لا تُعرض كروابط).
- `package.json` — يذكر الاعتماد على حزمة `@upstash/redis`.

## خطوات النشر

### 1. إنشاء حساب ورفع المشروع

1. أنشئ حسابًا مجانيًا على [vercel.com](https://vercel.com) (يمكن التسجيل
   مباشرة عبر GitHub أو البريد الإلكتروني).
2. **مهم — اختاروا طريقة الرفع بعناية، لأن هذا يحدّد كيف ستُحدَّث الصفحة
   لاحقًا:**
   - **عبر GitHub (المستحسن)**: ارفعوا هذا المجلد إلى مستودع (repository)
     جديد على GitHub، ثم من Vercel اختاروا **Add New... → Project → Import
     Git Repository** واربطوه بذلك المستودع. هذه الطريقة تجعل أي تحديث
     مستقبلي بسيطًا: تعدّلون الملف على GitHub وVercel ينشر النسخة الجديدة
     تلقائيًا على **نفس الرابط**.
   - **بالسحب والإفلات المباشر (Vercel Drop)**: ممكن للنشر الأول فقط، لكن
     انتبهوا: **كل عملية سحب وإفلات جديدة تُنشئ مشروعًا منفصلًا جديدًا
     برابط مختلف تمامًا** — Vercel Drop لا يُحدّث مشروعًا قائمًا مهما فعلتم.
     فإن استخدمتم هذه الطريقة، لتحديث الملفات لاحقًا (بعد النشر الأول) يجب
     ربط المشروع بـ GitHub بأثر رجعي من **Settings → Git → Connect Git
     Repository** بدل إعادة السحب والإفلات، وإلا فقدتم رابطكم الحالي وكل
     الإعدادات المرتبطة به (قاعدة البيانات، كلمة المرور...).
3. اترك كل الإعدادات على الوضع الافتراضي واضغط **Deploy**.

### 2. ربط قاعدة بيانات Redis عبر Upstash (خطوة ضرورية لمرة واحدة)

بدون هذه الخطوة، الصفحة تعمل لكنها لا تستطيع مشاركة البيانات بين الأجهزة.

ملاحظة: خدمة **Vercel KV** القديمة توقفت (تم استبدالها في ديسمبر 2024)،
فلن تجدوا خيارًا باسم "KV" في القائمة. البديل الرسمي المقدَّم من نفس متجر
Vercel (Marketplace) هو تكامل باسم **Upstash Redis**، وهو ما يستخدمه هذا
الملف. إن كانت واجهتكم بالفرنسية، ابحثوا عن الكلمات: **Stockage**
(Storage) ثم **Marketplace** أو **Browse Storage**، ثم اكتبوا **Upstash**
أو **Redis** في مربع البحث — الكلمتان "Upstash" و"Redis" لا تُترجَمان.

1. بعد نجاح النشر، افتح المشروع من لوحة تحكم Vercel.
2. اذهب إلى تبويب **Storage** (أو **Stockage** بالفرنسية).
3. اضغط على **Create Database** أو **Browse Marketplace** (أو ما يقابلها
   بالفرنسية)، ثم ابحثوا عن **Upstash**.
4. اختاروا تكامل **Upstash Redis**، واضغطوا **Add Integration** أو
   **Install** (**Installer**)، ثم أنشئوا قاعدة بيانات جديدة (اختاروا
   المنطقة الأقرب لكم إن طُلب ذلك) واربطوها بهذا المشروع (**Connect
   Project**).
5. بعد الربط، أعيدوا نشر المشروع مرة واحدة (تبويب **Deployments** → القائمة
   بجانب آخر نشر → **Redeploy**) حتى يحصل التطبيق على متغيرات الاتصال
   بقاعدة البيانات.

### 3. الحسابات والصلاحيات (ضروري)

- **المسؤول**: البريد `karama252@gmail.com` فقط. يطّلع ويعدّل. كلمة مروره هي
  متغيّر `ADMIN_PASSWORD` (لا تُحفظ في الكود). لا يمكن لأحد إنشاء حساب بهذا
  البريد من نموذج التسجيل.
- **باقي المستخدمين**: ينشئون حسابًا ببريدهم وكلمة مرور (8 أحرف فأكثر) من تبويب
  «إنشاء حساب»، ويحصلون على صلاحية **الاطلاع فقط**. الخادم يرفض أي محاولة كتابة
  منهم (حتى لو عبثوا بالصفحة).
- بدون تسجيل الدخول لا يظهر أي شيء من البيانات؛ وأسماء التلاميذ لم تعد داخل
  ملف الصفحة العام.

**الإعداد (مرة واحدة)** في Vercel → المشروع → **Settings → Environment
Variables**، أضيفوا متغيّرين:

| الاسم | القيمة |
|---|---|
| `ADMIN_PASSWORD` | كلمة مرور المسؤول التي تختارونها (قوية وطويلة) |
| `SESSION_SECRET` | سلسلة عشوائية طويلة (32 حرفًا على الأقل) تُوقَّع بها الجلسات؛ لا تشاركوها |

ثم **Deployments → (…) → Redeploy**. المتغيّر القديم `APP_PASSWORD` لم يعد
مستعملًا ويمكن حذفه.

ملاحظات:
- الجلسة تدوم 30 يومًا على الجهاز. لإخراج الجميع فورًا غيّروا `SESSION_SECRET`.
- لتغيير كلمة مرور المسؤول: عدّلوا `ADMIN_PASSWORD` وأعيدوا النشر.
- محاولات الدخول محدودة (10 محاولات كل 15 دقيقة لكل بريد/جهاز).
- لا يوجد تأكيد للبريد الإلكتروني: أي شخص يملك الرابط يستطيع إنشاء حساب اطلاع.

### 4. الاستخدام

بعد اكتمال ما سبق، ستجد رابطًا عامًا دائمًا يشبه:

```
https://ghiyab-app-xxxx.vercel.app
```

هذا هو الرابط الذي يفتحه كل مستخدم (بعد تسجيل الدخول أو إنشاء حساب). أي
تعديل (تسجيل غياب، إضافة تلميذ، استيراد لائحة...) يظهر تلقائيًا لدى كل من
يفتح نفس الرابط خلال ثوانٍ، بفضل التحديث الدوري كل 1.5 ثانية.

## ملاحظات

- الخطة المجانية على Vercel تكفي هذا الاستخدام (حجم البيانات صغير جدًا مقارنة
  بحدود الخطة المجانية لكل من Vercel وUpstash).
- **لتحديث التطبيق لاحقًا (مهم)**: إن كان المشروع مربوطًا بـ GitHub، عدّلوا
  الملف على GitHub (مباشرة من المتصفح أو برفع ملف جديد فوق القديم) وVercel
  سينشر النسخة الجديدة تلقائيًا على نفس الرابط خلال دقيقة تقريبًا. **لا
  تستخدموا السحب والإفلات المباشر على Vercel لتحديث مشروع قائم** — هذا
  دائمًا يُنشئ مشروعًا جديدًا منفصلًا برابط مختلف، ويفقدكم كل الإعدادات
  الحالية (قاعدة البيانات، كلمة المرور، الرابط الذي شاركتموه). إن لم يكن
  مشروعكم مربوطًا بـ GitHub بعد، اربطوه أولًا من **Settings → Git → Connect
  Git Repository** قبل أي تحديث.

## استعمال التطبيق لمؤسسة أخرى (نفس الكود، مشروع Vercel مستقل)

أنشئوا مشروع Vercel ثانيًا مربوطًا بنفس المستودع، واربطوه بنفس قاعدة Upstash Redis
(Storage ← Connect Project)، ثم أضيفوا له هذه المتغيّرات ليحصل على بيانات وحسابات منفصلة تمامًا:

| الاسم | القيمة |
|---|---|
| `KEY_PREFIX` | بادئة فريدة لمفاتيح هذه المؤسسة (مثال `marjaiya`)؛ الافتراضي `ghiyab` |
| `ADMIN_EMAIL` | بريد مسؤول هذه المؤسسة |
| `ADMIN_PASSWORD` | كلمة مرور المسؤول |
| `SESSION_SECRET` | سلسلة عشوائية مختلفة عن بقية المؤسسات (32 حرفًا فأكثر) |
| `INSTITUTION_NAME` | اسم المؤسسة الظاهر في الورقة (اختياري) |
| `LOGO_FILE` | اسم ملف الشعار داخل المجلد `logos` (مثال `marjaiya.jpg`)؛ بدونه يظهر الشعار الافتراضي (اختياري) |
| `SEED_BLANK` | `1` للبدء بقسم فارغ بدل لوائح المؤسسة الأولى (اختياري) |

## الإحصائيات (يومي / أسبوعي / شهري)

زر «📊 الإحصائيات» في أعلى الصفحة (متاح لكل الحسابات) يعرض مجموع ساعات الغياب وعدد التلاميذ
الغائبين ونسبتهم، **حسب التلاميذ أو حسب الأقسام أو حسب المستويات الدراسية**، يوميا أو أسبوعيا أو شهريا.

- **المرشّحات**: القسم والمستوى (تنطبق على الجدول والمبيانات والطباعة والتصدير).
- **المبيانات**: مبيان أعمدة أفقية للمجموعة المختارة (ساعات الغياب أو عدد الغائبين/أيام الغياب)
  + مبيان «التطور اليومي» عند اختيار أسبوع أو شهر. في عرض التلاميذ يُعرض أكثر 20 تلميذا غيابا.
- **الاستخراج**: «تحميل المبيانات (صورة PNG)»، و«تصدير إلى إكسيل» (ورقتان: الإحصائيات والتطور اليومي؛
  وملف CSV إذا تعذّر تحميل مكتبة إكسيل)، و«طباعة الإحصائيات» التي تتضمن المبيانات والجدول.
- تفاصيل التلاميذ تُحفظ مع ملخّص كل أسبوع (`abs` في `api/_stats.js`: الاسم + 30 خانة 0/1 للتلاميذ
  الذين غابوا فقط). الأسابيع المحفوظة قبل هذا التحديث لا تتضمنها، فتظهر لها رسالة توضيحية في عرض التلاميذ.

- الورقة تحتوي أسبوعا واحدا؛ ولحفظ الأسابيع السابقة يُخزَّن عند كل حفظ ملخّص صغير للأسبوع
  (مفتاحه يوم الاثنين المحسوب من تاريخ «من») في Redis تحت `<KEY_PREFIX>:history`.
  لذلك يجب تحديد تاريخ «من» لكل أسبوع.
- زر «🗓️ أسبوع جديد» (للمسؤول) يحفظ الأسبوع الحالي في السجل، يمسح الغياب، ويُقدّم التواريخ 7 أيام.
- المستوى الدراسي يُستنتج من اسم القسم (`1AIPC-2` ← `1AIPC`) ويمكن للمسؤول تعديله من صفحة الإحصائيات.

## إشعار ولي الأمر والاستدعاء (شبه آلي عبر واتساب)

- يحسب التطبيق ساعات غياب كل تلميذ **تراكميًا خلال الشهر الميلادي الجاري** (الأسابيع المؤرشفة في `/api/history` + الورقة المعروضة). كل خانة غياب = ساعة.
- **ساعة واحدة** ← «إشعار بالغياب»؛ **ثلاث ساعات فأكثر** ← «استدعاء للحضور» لمعالجة وضعية الغياب (الحدّان `NT_NOTICE` و`NT_SUMMONS` في `index.html`).
- لوحة «إشعارات تلقائية» تسرد الحالات المعلّقة في كل الأقسام، والرسالة جاهزة؛ زر «إرسال» يفتح واتساب برقم ولي الأمر (عمود «هاتف ولي الأمر»)، وزر «تم» يعلّمها معالَجة دون إرسال.
- بعد تأكيد تسجيل غياب يقترح التطبيق الإرسال فورًا عند بلوغ حدّ جديد (مرة واحدة لكل تلميذ ونوع رسالة في الجلسة).
- ما أُرسل محفوظ في `state.notices[YYYY-MM]["القسم|الاسم"]` فلا يتكرر الإشعار نفسه ولو فُتح التطبيق من جهاز آخر. يقتصر الإرسال والتعليم على حساب المسؤول.
- الإرسال التلقائي بلا نقرة غير ممكن بواتساب العادي؛ يتطلب خدمة مراسلة مدفوعة (SMS أو WhatsApp Business API).
- الأسابيع المؤرشفة قبل هذه الميزة لا تتضمن أسماء الغائبين، فلا تدخل في حساب الشهر.

## منع تسجيل غياب حصة لم يحن وقتها

- لا يقبل التطبيق تسجيل غياب في حصة تاريخها أو ساعة بدايتها لم تأتِ بعد (حسب تاريخ «من» للأسبوع وساعة الجهاز)؛ تظهر هذه الخانات بنقش رمادي وتُرفض بنقرة مع رسالة توضّح الموعد. حذف غياب سُجّل خطأً يبقى ممكنًا.
- بداية الحصص الافتراضية: صباحا 08:00 · 09:00 · 10:00، مساء 14:00 · 15:00 · 16:00، ويعدّلها المسؤول بزر «⏰ توقيت الحصص» (تُحفظ في `state.periodTimes`).
- إن لم يُحدَّد تاريخ «من» للأسبوع فلا يمكن معرفة موعد الحصص، فلا يُطبَّق المنع.
- المنع على مستوى واجهة التطبيق (حساب المسؤول)، ولا يفحصه الخادم.

## الرجوع إلى الأسبوع الماضي (تصحيح غياب سُجّل بالخطأ)

- زر «⏪ الأسبوع الماضي» في شريط الأدوات (للمسؤول) يعرض الأسبوع السابق في الجدول ليُصحَّح؛ وعند حفظ التعديل يُحدَّث ملخص ذلك الأسبوع في سجل الإحصائيات تلقائيًا. يظهر شريط أصفر يذكّر بأنكم في الأسبوع الماضي، ويتحوّل الزر إلى «العودة إلى الأسبوع الحالي».
- عند «أسبوع جديد» يُحفظ الأسبوع المنتهي كاملا (الغياب والمواد والأساتذة) في `state.other`، فيرجع كما كان. قبل أول «أسبوع جديد» يُبنى الأسبوع الماضي من سجل الإحصائيات (التلاميذ الغائبون فقط)، ولا يتوفر ذلك للأسابيع المؤرشفة قبل ميزة الإحصاء حسب التلميذ.
- لا يمكن بدء أسبوع جديد وأنتم تعرضون الأسبوع الماضي.

## صفّ الأيام ثابت أثناء التمرير

- الجدول يتمرّر داخل إطاره (بارتفاع أقصاه نحو 82% من الشاشة) فيبقى صفّا «أيام الأسبوع» و«الحصص» ظاهرين أعلاه كلما نزلتم في لائحة التلاميذ.
- يتكرّر الصفّان أيضًا أسفل اللائحة (بعد سطر مجموع الغياب في الحصة).

## عدد الحصص صباحا ومساء (إضافة حصة أو حذفها)

زر «🧮 عدد الحصص» (للمشرف فقط) يضبط عدد الحصص في اليوم ليلائم النظام الدراسي للمؤسسة: من 0 إلى 8 حصص صباحا ومثلها مساء (يجب أن تبقى فترة واحدة على الأقل، فيمكن لمؤسسة تدرّس صباحا فقط أن تحذف كل الحصص المسائية). الافتراضي 3 + 3 كما كان.

- **إضافة** حصة تُضاف في آخر الفترة (ح4 مثلا) لكل أيام الأسبوع وكل الأقسام، وتُعطى توقيتا افتراضيا بعد الحصة السابقة بساعة (يُعدَّل من «⏰ توقيت الحصص»).
- **حذف** حصة يسأل عن رقمها ويطلب التأكيد مع ذكر عدد ساعات الغياب المسجلة فيها؛ الحصص التي بعدها يتغيّر ترقيمها وتبقى موادها وأساتذتها وغياباتها مع حصصها الصحيحة.
- التغيير يُطبَّق على الأسبوع المعروض وعلى «الأسبوع الماضي» المحفوظ في الجدول؛ الأسابيع المؤرشفة في الإحصائيات تحتفظ بتخطيطها الخاص (يُخزَّن `pc` مع كل ملخّص أسبوع) فتبقى أرقامها صحيحة ولا تتغير.
- التخزين: `state.pc = [صباحا, مساء]` ضمن حالة الجدول نفسها، فكل مشروع Vercel له إعداداته الخاصة (مدرسة ابتدائية بنظام مختلف عن الإعدادية) من نفس الكود.
